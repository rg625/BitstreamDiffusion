\section{Task 3 --- Nature of errors on TinyGSM \yes}
Taxonomy: \textbf{T1} non-executing program, \textbf{T2} executes but wrong
number, \textbf{T3} token-level degeneration.

\textbf{The baseline's dominant failure is T1 (98/250 = 39\%)} --- the model
emits programs that do not run. Under guidance, \textbf{T2 falls while T1
rises}: guidance damages \emph{code validity}, not arithmetic reasoning. T3
appears only under strong guidance. Invalid-token rate is
$3\times10^{-6}$--$5\times10^{-5}$, i.e. bit$\to$token decoding is not the
problem.

\section{Task 4a --- Temporal ordering at inference \yes}
Schedule: $t_j(t)=\mathrm{clip}(t(1+w)-w\,u_j,0,1)$, with $u_j$ a denoising
\emph{priority} over the generated \textbf{suffix only}; prompt keeps the global
$\sigma$. Verified causally active: at $w{=}0.5$ the per-position $\sigma$
spread is $192\times$, first suffix token cleanest; at $w{=}0$ it is bit-identical
to the current model.

512 steps does not rescue it, so it is not a too-short-trajectory artefact.

\section{Task 4b --- Temporal ordering, TRAINED \no\ (inconclusive)}
Implementation is complete and tested (24 tests): $\sigma$ is drawn per example,
mapped to normalised time by the \emph{same} map the sampler uses, offset per
token, mapped back and expanded blockwise to bits. All three modes provably
produce \emph{different} $\sigma$ fields; L2R and R2L are mirror images; random
is redrawn per example \emph{and} per step; $w{=}0$ leaves the gradient hash
unchanged. Four arms (control / L2R / R2L / random, $w{=}0.25$) fine-tuned from
the same production 500k checkpoint at \code{lr 3e-5}; none diverged.

\textbf{The experiment is nonetheless inconclusive, because the control arm is
degenerate.} At the matched 5k checkpoint the uniform-$\sigma$ control scores
\textbf{0.0000} while the ordered arms score 0.07--0.12. Taken at face value
that reads as ``ordering massively improves TinyGSM''. It is not credible and
is not claimed.

\textbf{Diagnosis.} The control's weights moved only 4.65\% from init and its
EMA is healthy, so the model is not destroyed. The likely cause is the
$\sigma$-\emph{sampling} distribution: production converged under its
entropy-adapted draw, but a fresh fine-tune restarts the entropy warmup
(\code{entropy\_warmup\_steps=40000}) and therefore trains under the base
log-normal draw. Every arm suffers that mismatch; the control, whose $\sigma$
field is pure and unspread, appears to suffer it most. Verified under two
independent sampling schedules (entropic and karras), so it is not a decoder
artefact.

\textbf{What is needed:} a control that provably retains the init's accuracy ---
either by preserving the entropy schedule across the fine-tune, or by training
all arms from scratch under a common schedule. Not attempted within this window.

\section{Task 5 --- Predict logits instead of raw bits}
\textbf{Softmax is not a distinct objective, and this is proved rather than
assumed.} The model already emits \textbf{one logit per bit}
(\code{out\_dim=1}, \code{vocab\_size=2}). A 2-class softmax is shift-invariant,
so it has a single degree of freedom $d=z_1-z_0$ and
\[
\mathrm{softmax}(z_0,z_1)_1=\sigma(d),\qquad
\mathrm{CE}(z,y)=\mathrm{BCEWithLogits}(d,y)
\]
exactly; the 2-class head merely splits the same gradient across two logits
($\partial L/\partial z_1=-\partial L/\partial z_0=\partial L/\partial d$).
Verified to $10^{-12}$ in 5 tests. \textbf{No GPU was spent on it.}

\subsection*{The distinction I initially got wrong}
The task asked for \emph{``bitstream embedding but predict logits''}. I first
resolved that as a per-bit softmax and proved it redundant. That proof is
correct but answers a \textbf{narrower} question than was asked:

\begin{center}\small
\begin{tabular}{@{}lcc@{}}
\toprule
Parameterisation & Degrees of freedom & Distinct from BCE?\\ \midrule
2-class softmax \emph{per bit} & 1 \ ($z_1-z_0$) & \textbf{No} --- exactly BCE\\
\textbf{$V$-way softmax \emph{per token}} & \textbf{49{,}152} & \textbf{Yes} --- strictly more expressive\\
\bottomrule
\end{tabular}
\end{center}

The binary head predicts \textbf{16 independent Bernoullis} per token, so it can
only represent a \emph{product} distribution over that token's bits. A $V$-way
categorical over the 49{,}153-token vocabulary can represent \emph{any}
distribution over tokens, including the bit correlations the binary head
structurally cannot express. \textbf{That is the ``added flexibility'' the task
was about, and it is a real experiment.}

\subsection*{$V$-way token softmax --- implemented, not yet run \run}
Now wired for TinyGSM:
\begin{center}\small
\code{representation=tokens \ \ V=49153 \ \ S=512 \ \ patch\_size=1 \ \ out\_dim=49153}\\
\code{loss=token\_ce \ \ data\_center=1/V=2.03e-05 \ \ p\_uncond=0.1 \ \ edm \ \ clamp off}
\end{center}
Two defects had to be fixed beyond the config. The TinyGSM dataset returned
\emph{bits}, but the trainer's token path indexes \code{x0} as \emph{class
indices} --- it would have trained silently on the wrong target space; it now
returns token IDs and a token-level prefix mask, with the binary path
bit-identical (tested). And \code{data\_center} must be $1/V$, not the bits
value 0.5: a one-hot token's mean is $1/49153$, and centring the diffusion at
0.5 would place it nowhere near the data manifold. 7 new tests; 431 pass.

\textbf{Not yet run.} The open question is memory: the logits tensor is
$[B,512,49153]$, i.e.\ \textbf{26 GB in bf16} at global batch 512 ($\approx$6.4
GB per GPU over 4 ranks) before activations, so the loss is evaluated in chunks
rather than materialised. A 300-step smoke test is queued. If it OOMs, the batch
drops \emph{and the binary control is rerun at the same batch}, so the
comparison never confounds representation with batch size.

\textbf{Caveat.} Unlike SM-vs-CE this is \emph{not} a one-variable experiment:
representation, output dimensionality, loss and memory profile all change
together. And with accuracy at 0.0000 for 5k/10k and the first non-zero point at
200k, a 50k token run will most likely also score zero --- the readable endpoints
would be stability and the loss/gradient diagnostics, not accuracy.

plus three output paths). Evaluated on 1319 problems $\times$ 3 seeds,
karras/DDIM, identical settings.

\textbf{CE's theoretical advantage does not appear.} The motivation for CE was
that its gradient lacks the $D(1{-}D)$ factor that suppresses SM's. In a

decimals. \textbf{This is the cleanest test the objective branch has had, and it
is negative.}

\emph{Caveat, stated deliberately:} \code{lr 3e-5} establishes a \textbf{stable}
regime, not a \textbf{tuned} one. These arms are compared only to each other,
never to production's 3e-4 trajectory. A comparison at a tuned learning rate and
a convergent budget remains untested.

\section{The infrastructural finding (not on the task list)}
\begin{center}
\includegraphics[width=0.60\textwidth]{fig/lr_stability.pdf}
\end{center}
Eight from-scratch runs diverged before ${\sim}12$k steps at \code{lr 3e-4},
\textbf{including the production-era commit itself}. Ruled out along the way:
corpus ($\sigma_{\text{data}}$ fingerprint matches to ${\sim}8$ s.f.), data
config (identical on 22 keys), our post-June code (fp32 forward+loss+backward
\textbf{bit-identical} to the production commit), and the Python interpreter ---
a 3.10 rebuild diverged at 5{,}346, falsifying a hypothesis I had put weight on.

\textbf{At \code{lr 3e-5} a from-scratch run reached 20{,}000 steps cleanly},
as did all four ordering arms. The learning rate is the identified factor.
\emph{Caveat:} 3e-5 establishes a \textbf{stable} regime, not a \textbf{tuned}
one. It is 10$\times$ below production's value, so absolute accuracies in this
regime are compared only against the matched control and never against
production's 3e-4 trajectory.

\section{Why accuracy could not be measured on short runs}
\begin{center}
\includegraphics[width=0.52\textwidth]{fig/accuracy_vs_steps.pdf}
\end{center}
GSM8K accuracy is \textbf{exactly 0.0000 at both 5k and 10k} training steps
(measured, both objectives), and the first non-zero point we have is 0.2024 at
200k. Combined with divergence before 12k, the trainable range and the range
where accuracy exists \textbf{did not overlap} --- which is why the objective
branch was blocked rather than merely slow.
